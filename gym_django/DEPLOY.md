# Deployment Guide (Render.com) - Django version

The project runs as a Python WSGI web service (**Gunicorn**) using the included `render.yaml` Blueprint.

## Option 1: Blueprint (`render.yaml`)
1. Push the repository to GitHub (`.gitignore` excludes `.venv/`, `__pycache__/`, `*.db`, `.env`, `staticfiles/`).
2. Render Dashboard -> **New + -> Blueprint**, connect the repository.
3. Render reads `render.yaml`:
   - **Build Command:** `pip install -r requirements.txt && python manage.py collectstatic --noinput`
   - **Start Command:** `python manage.py migrate --noinput && python manage.py seed_demo && gunicorn config.wsgi:application --workers 1 --threads 4`
   - **Environment Variables:** `DJANGO_SECRET_KEY` (generated by Render), `DJANGO_DEBUG=0`, `DATABASE_PATH=gym.db`, `PYTHON_VERSION=3.13.1`
4. Click **Apply**. The database is migrated and seeded on every start (`seed_demo` does nothing if data already exists).
5. Open `https://<service-name>.onrender.com`. Render's hostname is added to `ALLOWED_HOSTS` / `CSRF_TRUSTED_ORIGINS` automatically (`RENDER_EXTERNAL_HOSTNAME`).

## Option 2: Manual Web Service
Runtime **Python 3**, same Build and Start commands as above, and the environment variables
`DJANGO_SECRET_KEY` (strong random string), `DJANGO_DEBUG=0`, `DATABASE_PATH=gym.db`
(or `/var/data/gym.db` with a Render Persistent Disk).

## Production notes
- **SQLite persistence:** the Free tier has an ephemeral filesystem, so `gym.db` resets on every deploy/restart
  (and is re-seeded). For persistent data attach a Render Disk and set `DATABASE_PATH=/var/data/gym.db`, or move to PostgreSQL.
- **One worker:** keep `--workers 1 --threads 4` with SQLite to avoid write-lock contention.
- **Password reset links:** no SMTP is configured, so `/forgot-password` shows the reset URL on the page (demo mode).
  Configure Django's email backend before real production use.
- **Django admin:** available at `/django-admin/` (create a superuser with `python manage.py createsuperuser`).
  The team's own admin dashboard stays at `/admin`.

## Local commands (replace the Flask ones)
| Flask | Django |
|---|---|
| `python app.py` | `python manage.py runserver` |
| `python app.py --reset` | `python manage.py seed_demo --reset` |
| `python app.py --check` | `python manage.py check` and `python manage.py makemigrations --check` |
| `python -m unittest -v test_app` | `python manage.py test -v 2` |
